# Community project showcase

Built something useful from the guide? Share the result and one decision another learner can learn from. A small CSV tool with clear behavior and tests can be a good example; a flagship is not required.

**No community projects have been reviewed or listed yet.** This page is an invitation, not a collection of implied endorsements or invented success stories.

## What makes a useful submission

- A public, inspectable artifact with at least one working behavior and a clear current status.
- Your actual contribution, with collaborators and material AI assistance credited.
- A reproducible small run, executed test, evaluation report, or concrete failure analysis.
- Honest boundaries: measured results have context; prototypes and unmeasured work are labeled.
- A takeaway another learner could use, such as a corrected leakage boundary or a clearer setup instruction.

Keep the work's own code, data, and model licenses visible. Listing a link here would not change those licenses or certify security, production readiness, or hiring suitability.

## Share a project

Use the [project feedback form](https://github.com/MJmuhammadjihad/AI-ML-Engineering-Portfolio/issues/new?template=project_feedback.yml). Ask one specific question and select the optional showcase permission if you want the maintainer to consider listing your work. An issue without that opt-in is a feedback request only. Review depends on availability; a submission does not promise inclusion.

A focused pull request adding a proposed entry is also welcome. Submit your own work or a project whose authors have agreed to the listing. Include this information:

```markdown
### [Project name](public repository or case-study URL)

- Author: [public handle or name you choose to publish]
- Status: [finished tool / working prototype / evaluated release / controlled drill]
- Problem and contribution: [one or two precise sentences]
- Evidence: [small run, tests, evaluation, or actual failure report]
- Result: [actual metric with baseline, split and N, or “not measured”]
- Lesson: [one decision, mistake, or tradeoff worth learning from]
- Main limitation: [what the work cannot establish yet]
```

Do not include private application notes, personal contact details, or unmeasured claims of business impact. Share a link and enough evidence to start a useful technical conversation.

## If your work changes

Update its status and evidence links with a small pull request. Mark a contribution submitted, reviewed, or merged according to its actual state. If you want an entry removed, open an issue identifying the entry; the maintainer can remove the listing, though public Git history and copies may remain.
